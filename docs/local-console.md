# 로컬 설정 홈페이지 구현 및 검증

2026-11-15. 홈페이지 주소: http://127.0.0.1:8765/ . 실행은 루트 README의 `start-web.ps1` 또는 `web_server.py` 명령을 따른다.

## 구현

- 정책 추가·수정·삭제·목록: 이름, 정확한 톡방 제목, 키워드 배열, 점검 주기, 활성 여부.
- 전역 자동 점검과 정책별 활성 조건을 함께 적용. 새 설치는 자동 점검 꺼짐. 설정은 재시작 후 유지.
- 수동 점검 대기열과 단일 순차 작업 실행기. 여러 정책의 동일 방 수집은 공통 대화 DB를 사용하고 감지 기준점은 정책별로 관리.
- 기존 보관 대화 건수와 TXT 내려받기. 기존 SQLite 테이블을 삭제하거나 초기화하지 않음.
- 최근 점검 60개, 감지 100개, 설정 변경 60개를 화면 및 MCP 상태 조회에서 제공. DB에는 전체 기록 유지.
- 웹과 stdio 정책 MCP가 `monitor.sqlite3`를 공유. 실제 수집은 웹 서버의 작업 실행기가 수행.
- Host·Origin 검증, 요청 토큰, 외부 사이트 fetch 차단, loopback 바인딩, JSON 크기 제한, HTML escaping 및 CSP 적용.

## 검증 결과

- 전체 자동 테스트 20개 통과. 정책 저장·검증·재시작·삭제, 자동 점검의 꺼짐/기한/중지, 같은 방 여러 정책의 독립 감지, 기존 메시지 재알림 방지, 실패 시 기준점 보존 포함.
- 실제 SDK stdio MCP 클라이언트로 초기화·도구 목록·정책 생성·조회·삭제를 확인. 화면 조작 허용 없이 수동 점검을 요청하면 오류이며 대기열을 만들지 않음.
- HTTP 통합 테스트에서 토큰 없는 변경 요청과 외부 Origin 요청 403, 정상 정책 저장 및 조회 성공.
- 실제 로컬 브라우저에서 정책 생성과 5분→10분→5분 수정, 설정 변경 로그 반영, 기존 메시지 36개 표시, TXT 내려받기 링크 생성 확인.
- 화면 조작 안내를 체크하지 않은 ‘지금 점검’ 클릭은 안내만 표시하고 실제 점검을 실행하지 않음.
- 초기 사용자 정책: `운영진 키워드 모니터링`, 방 `테스트 톡방`, 키워드 `테스트 키워드`, 주기 300초. 정책별 활성 및 전역 자동 점검 모두 꺼짐. 화면에서 자유롭게 수정 가능.

## 제한

이번 웹 구현 검증에서는 실제 카카오톡 점검을 새로 실행하지 않았다. 이전 수집 데모의 포커스 충돌 및 과거 구간 연결 한계는 그대로 남아 있다. 수집 성공이 운영정책 승인을 뜻하지 않는다. [수집기 검증](collector-demo.md), [정책 검토](feasibility.md).

MCP 클라이언트의 정책 수정 요청은 실제 데이터에 반영된다. 감지 조회 응답에는 대화 본문이 포함되므로 연결한 에이전트의 데이터 전송 범위를 확인한다. Pickle 제품 자체의 설정·연결은 미검증이다.
