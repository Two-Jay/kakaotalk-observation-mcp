# 카카오톡 실시간 모니터링 MCP 사전 검토

검토일: 2026-11-14 (Asia/Seoul). 공개 공식 문서와 현재 저장소 코드 기준이다. 실제 카카오톡 대화 수집, 계정 접근, 문의 발송은 수행하지 않았다.

## 결론

**일반·단체·오픈채팅방의 실시간 자동 수집과 운영정책 준수를 동시에 충족하는 공개 공식 연동 경로를 이번 조사에서 확인하지 못했다.** MCP, localhost 설정 화면, 정책 CRUD, 주기 실행, 저장·로그는 구현 가능한 영역이다. 현재 결정해야 할 부분은 카카오톡에서 메시지를 받는 수집 경로다.

PC 화면 복사·OCR·OS 알림 관찰은 기술적 후보이지만, 카카오가 해당 용도를 허용했다는 근거가 되지는 않는다. 반대로 모든 GUI 자동화를 일률적으로 금지한다는 결론도 확인한 문구만으로 내리지 않는다. 사용자가 요구한 ‘정책에 저촉되지 않는 실시간 수집’을 충족한다고 표시하려면 정확한 동작·대상·저장·에이전트 제공 범위를 제시한 카카오 측 확인이 먼저 필요하다. 이것은 공개 자료의 공백에 대한 개발 판단이며 법적 결론은 아니다.

## 공식 자료로 확인한 사실

- 2025-10-24 카카오 데브톡 답변은 일반채팅·오픈채팅·비즈니스 채널 내역 조회 문의에 이용자간 대화 조회 기능을 제공하지 않는다고 설명했다. 채널과 이용자의 대화에는 상담톡·채널 챗봇을 안내한다. [카카오톡 내용 API](https://devtalk.kakao.com/t/api/146860)
- 더 최근인 2026-02-09 답변도 개인간 메시지 내용을 외부 서비스에 연동하도록 제공하지 않는다고 설명하고, 채널과 문의자 간 상담은 딜러 계약을 통한 상담톡을 안내한다. 현재 공개 API 목록에도 일반 톡방 메시지 수신·내역 조회가 없다. [연동 가능 여부 답변](https://devtalk.kakao.com/t/topic/148362/4), [REST API 레퍼런스](https://developers.kakao.com/docs/ko/rest-api/reference)
- 채널 관리자 권한만으로 1:1 수신·내역을 읽을 수 있는지 묻는 2026-01-29 답변은 공식 딜러의 상담톡을 안내한다. 상담톡은 기존 개인 단톡방을 그대로 모니터링하는 API가 아니다. [채널 수신·Webhook 문의](https://devtalk.kakao.com/t/rest-api-1-1-webhook/148198), [상담톡 안내](https://business.kakao.com/info/cstalk/)
- 카카오톡 운영정책은 비정상 프로그램을 통한 프로토콜·API 부정 호출, 타인 정보의 부정 수집·이용·제공, 기술적 보호조치 무력화 등의 행위를 제한한다. 읽기 전용·개인 사용·로컬 저장만으로 자동 예외가 된다는 근거는 확인하지 못했다. [카카오톡 운영정책](https://talksafety.kakao.com/policy/stability/abnormalusage)

공식 문서가 제공하는 범위와 특정 구현의 정책 허용 여부는 구분해야 한다. ‘API가 없다’는 사실만으로 모든 로컬 화면 읽기가 금지라고 단정할 수 없고, ‘Windows 공식 API를 쓴다’는 사실만으로 카카오가 이를 승인했다고 단정할 수도 없다.

## 수집 방식 비교

| 방식 | 기술적 범위·한계 | 이번 검토의 판단 |
|---|---|---|
| 일반 톡방 공식 수신 API | 확인한 공개 API에서 제공하지 않음 | 요구한 수집 구현에 사용 불가 |
| PC 창 자동 복사 | 열린 대화 목록에서 복사 가능한 부분만 획득. 포커스·클립보드·카톡 버전에 의존 | 정책 허용 근거 및 실제 동작 검증 필요 |
| 화면 캡처/OCR | 캡처한 화면에 있는 내용만 판독. 화면 밖 메시지·가림·인식 오류 가능 | 전체 대화 보존이나 누락 없는 감지를 보장하지 못함. 정책 확인 별도 |
| Windows 알림 관찰 | Microsoft Notification Listener는 사용자 권한을 받아 Windows 알림을 읽음. 실제 카톡이 노출하는 알림 형식·누락 조건은 미검증 | 전체 대화기록 수집 대체재로 취급할 수 없음. 카카오 허용 여부 별도 |
| 직접 내보낸 파일 | 파일에 들어 있는 대화를 분석·보관할 수 있지만 새 파일을 내보내야 갱신됨 | 사용자가 필수로 정한 실시간 자동 수집을 충족하지 못함 |
| 상담톡 연동 | 채널과 고객의 상담 대화를 공식 연동하는 경로 | 대상이 채널 상담으로 바뀌는 경우 검토 가능. 기존 단톡방 요구에는 부합하지 않음 |
| 비공개 프로토콜 호출·역분석 연동 | 공식 허용 범위 밖의 접근이 문제 될 수 있음 | 정책 준수가 필수인 본 설계의 해결책으로 채택하지 않음 |

Windows Notification Listener의 권한과 알림 접근 범위는 [Microsoft 공식 문서](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/app-notifications/notification-listener)를 따른다. UI Automation 자체는 접근성·자동 테스트 등을 위한 일반 인터페이스이며 특정 앱 데이터 수집에 대한 그 앱 운영사의 허락을 제공하지 않는다. [Microsoft UI Automation 소개](https://learn.microsoft.com/en-us/windows/win32/winauto/entry-uiauto-win32)

표의 복사·OCR 누락 가능성과 ‘알림만으로 전체 대화 보존 불가’는 입력 범위에 따른 기술적 판단이다. 현재 설치된 카카오톡을 대상으로 실험한 결과가 아니다. 특히 메시지를 발견하지 못한 결과는 수집 범위·상태를 확인하기 전까지 ‘언급 없음’으로 표현하면 안 된다.

## 기존 코드 상태

[`windows_source.py`](../kakao-mention-watch/kakao-mention-watch/windows_source.py)는 pywinauto의 `win32` backend로 정확한 제목의 열린 카카오톡 창과 대화 목록을 찾고, 포커스를 옮긴 뒤 Ctrl+A/C로 복사한다. 이는 공식 메시지 수신 API가 아니며 UI Automation backend 구현도 아니다. 최소화된 창은 거부하고, 클립보드와 이전 포커스 복원을 시도한다. 실제 설치본에서 동작 검증은 되어 있지 않다.

[`watcher.py`](../kakao-mention-watch/kakao-mention-watch/watcher.py)는 이전 메시지 해시와 언급 이벤트·일부 문맥을 보관한다. **현재 모든 대화 원문을 보존하지 않으며**, 새 MCP·웹 설정 서버도 구현되어 있지 않다. 기존 파일 기반 테스트 통과는 카카오톡 자동 수집 또는 정책 준수의 증거가 아니다. 기존 코드는 이번 조사에서 변경하거나 실행하지 않았다.

## 아직 확인되지 않은 것

- 카카오가 사용자 본인 PC에서 본인 참여 방을 주기적으로 복사/OCR/알림 관찰하고 원문을 보관하는 구체적 사용 방식을 허용하는지.
- 참여자 동의, 보관 기간, 이름·본문 저장, 외부 에이전트 제공에 대해 요구되는 조건. 본인 계정이나 방장의 동의만으로 모든 요건이 충족된다고 가정하지 않는다.
- MCP 서버가 localhost여도 연결한 에이전트가 대화를 클라우드 모델로 전송할 수 있다. 정책 문의에서 ‘로컬 저장’과 ‘외부 모델 제공’을 구분해야 한다.
- 2026-11-14 데브톡 목록에는 `AI_TOP_100 Bot API의 일반 운영용 앱 사용 권한 문의`가 있고 조사 시점 답변 수는 0으로 보였다. 본문은 접근하지 못했다. 대회 API의 일반 공개·일반 톡방 읽기 권한을 입증하는 근거가 아니며 이 자료로 기존 결론을 바꾸지 않았다. [데브톡 목록](https://devtalk.kakao.com/latest), [문의 주소](https://devtalk.kakao.com/t/ai-top-100-bot-api/152792)

## 카카오에 전달할 문의 초안 — 미발송

제목: 본인 참여 카카오톡 방의 로컬 실시간 키워드 감지 도구 허용 여부 문의

> Windows PC에서 본인이 참여 중인 지정 카카오톡 대화방의 새 메시지에 특정 키워드가 포함되는지 확인하는 개인용 도구를 검토하고 있습니다. 일반채팅·단체채팅·오픈채팅 각각 허용 여부를 확인하고 싶습니다.
>
> 도구는 메시지를 보내지 않고, 로그인 정보·비공개 프로토콜·카카오톡 내부 DB·프로세스 메모리에 접근하지 않습니다. 후보 수집 방식은 (1) 열린 대화 목록에 키보드 복사 명령을 보내는 방식, (2) 선택한 카카오톡 창을 캡처해 로컬 OCR로 읽는 방식, (3) 사용자가 허용한 Windows 알림을 관찰하는 방식입니다. 실제 사용할 방 수와 점검 간격을 설정하며, 새 메시지 본문·발신자·표시 시각을 로컬 DB에 저장하고 키워드가 일치하면 이벤트를 남기려 합니다.
>
> 설정은 localhost 웹페이지와 로컬 MCP 서버로 관리합니다. 연결 에이전트에는 정책·감지 결과를 제공하며, 대화 원문·문맥을 제공할 경우 클라우드 모델에 전달될 가능성이 있으므로 ‘로컬 처리만 하는 경우’와 ‘외부 모델에 전달하는 경우’를 구분해 확인받고 싶습니다.
>
> 1. 각 수집 방식이 이용약관·카카오톡 운영정책상 허용되는지, 사전 승인이나 별도 계약이 필요한지 알려주시겠습니까?
> 2. 참여자 동의, 대화 원문 보관, 보관 기간, 발신자 식별정보, 외부 에이전트 제공에 필요한 조건은 무엇입니까?
> 3. 이를 대체하는 공식 일반 톡방 메시지 수신 API나 제휴 경로가 있습니까? AI_TOP_100 등에서 쓰인 Bot API가 이 용도로 일반 제공되는지도 확인 부탁드립니다.
> 4. 개인 전용 이용과 프로그램의 타인 배포·유료 제공 사이에 허용 조건이 다릅니까?

문의에는 확정한 방 유형·수·점검 간격·보관 기간·외부 전달 여부를 추가한다. [카카오 고객센터](https://cs.kakao.com/)에서 운영정책 적용 여부를, [카카오 데브톡](https://devtalk.kakao.com/)에서 공식 API 지원 범위를 확인할 수 있다. 답변을 받기 전에는 해당 확인이 완료됐다고 표시하지 않는다.

## 다음 개발 결정

현재 조건을 그대로 유지하면 수집 구현 확정은 보류한다. 카카오의 답변이 허용 범위를 명시하면 그 범위에 맞춘 수집기를 먼저 검증하고 MCP·설정 화면·정책 관리·저장 계층에 연결한다. 후보 방식이 불허되고 대체 공식 수집 경로도 없다면, 대상 대화를 공식 연동 가능한 채널 상담 등으로 바꾸거나 실시간 자동 수집 조건을 변경해야 한다. 허용 여부가 불명확하게 남으면 정책 준수 조건도 미확정으로 유지한다. 파일 방식으로 바꿔 구현하는 것은 사용자가 선택한 현재 요구의 완료가 아니다.
