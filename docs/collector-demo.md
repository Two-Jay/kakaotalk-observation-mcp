# 독립 수집기 및 MCP 데모 검증

검증 환경: Windows, Python 3.14.7, pywinauto 0.6.8, pywin32 312, MCP SDK 1.30.0. 실제 검증 방은 사용자가 지정한 `테스트 톡방`. 대화 전송은 수행하지 않았다.

## 확인한 결과

- 2026-11-14: 독립 Python 프로세스가 `KakaoTalk.exe`를 찾고 메인 검색란에 방 이름을 입력했다. 검색 결과를 열고 정확한 제목의 방 활성화를 확인했다.
- 2026-11-14: 열린 방의 대화 목록에서 36개 메시지를 복사하고 `data/demo/collector.sqlite3` 및 `data/demo/transcript-8b987c13e371.txt`에 저장했다. 전체 과거 대화 수집을 뜻하지 않는다.
- 2026-11-15: 화면 조작 기능 없는 SDK 클라이언트에서 MCP 초기화·도구 목록 조회·창 탐색·검색·방 열기가 성공했다. 수집 단계도 복사까지 도달했지만 어제 기준점과 연결되지 않아 `coverage_gap`으로 중단했다. MCP 전체 성공 검증은 아직 완료되지 않았다.
- 공백 진단: 최초 저장은 11월 14일 메시지 36개, 현재 복사는 11월 15일 메시지 33개였다. 8페이지 위로 이동하자 123개로 확대됐지만 이전 기록과의 일치는 없었다. 이 검사에서 본문·이름은 출력하지 않았다.
- 최대 32페이지의 제한된 과거 로딩 및 연결 확인을 구현했다. 실화면에서 이 기능의 최종 성공은 아직 검증되지 않았다. 이어진 실행에서 다른 창으로 포커스가 이동해 키 입력 전에 중단했다.
- 자동 테스트 15개 통과: 기존 감지기 13개와 저장·재시작·중복 방지·공백·TXT 복구 테스트 2개. 실제 GUI 연결 성공을 대체하는 검증은 아니다.

## 발견하고 수정한 문제

1. 하위 컨트롤에 `set_focus()`를 호출해 창 활성화와 키보드 포커스를 혼동했다. 하위 컨트롤은 `set_keyboard_focus()`로 수정하고 입력 전 실제 포커스를 검증한다.
2. MCP 자식 수집기에 서버의 stdin 파이프가 상속되어 실행이 타임아웃됐다. `stdin=subprocess.DEVNULL`로 분리하자 동일 MCP 호출의 창 탐색이 성공했다. 통합 클라이언트가 이 경로를 재현한다.
3. 데스크톱 탐색 중 임시 창이 사라질 때 전체 작업이 실패했다. 해당 `InvalidWindowHandle`만 건너뛰도록 수정했다.
4. SQLite 연결의 context manager가 연결 자체를 닫지 않아 Windows에서 임시 파일 정리가 실패했다. 명시적 close를 추가했고 저장 테스트가 통과했다.

## 백그라운드 읽기 검사 — 2026-11-15

사용자가 PC 작업과 충돌하지 않는 수집을 요청하여 읽기 전용 `background_probe.py`를 실행했다. 검사 전후 foreground 핸들이 같았으며 창 활성화·키 입력·클립보드 변경을 하지 않았다.

관측한 대상 대화 목록 클래스는 `EVA_VH_ListControl_Dblclk`였다.

| 항목 | 관측 |
|---|---|
| UIA Text 패턴 | 미지원 (`NoPatternInterfaceError`) |
| UIA Value 패턴 | 미지원 (`NoPatternInterfaceError`) |
| Legacy 접근성 Value | 지원하지만 문자열 길이 0 |
| 접근성 하위 요소 | 1개, 이름 있는 요소 0개 |

원시 메타데이터는 `data/demo/background-probe.json`에 있다. 이 설치본에서 표준 접근성 API를 통해 대화 본문을 백그라운드로 얻는 경로를 확인하지 못했다는 결과다. 모든 다른 백그라운드 방식이 불가능하다는 결론은 아니다.

Microsoft의 TextPattern은 앱의 provider 지원이 필요하다. [공식 문서](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-about-text-and-textrange-patterns). `WM_COPY`는 기본적으로 edit/combo의 선택 텍스트 복사용이며, 이 사용자 정의 대화 목록의 전체 선택·스크롤까지 지원한다는 근거는 없다. 이 방식은 검사하지 않았다. [공식 문서](https://learn.microsoft.com/en-us/windows/win32/dataxchg/wm-copy).

현재 전경 수집기는 사용자의 동시 조작과 충돌할 수 있다. 사용자의 답변이 백그라운드 가능 여부에 대한 질문이었으므로 PC 조작을 멈췄다는 승인으로 간주하지 않았고, 추가 전경 조작은 중단했다. 별도 PC 또는 별도 GUI 세션에 카카오톡·수집기를 배치하면 일상 작업의 입력과 분리할 수 있지만, 로그인 유지·절전·세션 및 카카오 접속 조건을 별도 검증해야 한다.

## 남은 검증

전경 데모를 계속한다면 입력을 사용하지 않는 시간에 `demo_mcp_client.py --live`를 실행해 기준점 연결 및 반복 호출의 신규 저장 0개를 확인한다. 실제 새 메시지가 발생한 뒤 그 메시지만 추가되는 실화면 검증도 필요하다. 자동 메시지 전송은 데모에 포함하지 않는다.

정책 관리 웹·주기 실행기는 현재 데모 범위에서 구현하지 않았다. Pickle 실제 등록은 미검증이다. 기술적 성공과 카카오 정책 허용 여부는 별개다.
